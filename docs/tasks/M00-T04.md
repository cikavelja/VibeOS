# M00-T04 — Create CI quality gates

Priority: MVP | Requirement: REQ-00-04

## Dependencies
M00-T03

## Objective and scope
Implement only create ci quality gates in the repository infrastructure. Reuse existing contracts; inspect affected modules before adding new abstractions.

## Out of scope
Other task capabilities, unrelated refactoring, speculative dependencies, changing accepted contracts without an ADR.

## Acceptance criteria
- AC-01: CI runs frontend and backend checks and fails on a deliberately failing test.
- AC-02: Invalid input and relevant failure paths are handled without silent success or unauthorized side effects.
- AC-03: Existing applicable regression tests pass and architecture/security constraints remain intact.

## Required verification
- Add automated tests that directly exercise AC-01 and AC-02; use integration or Playwright tests for cross-boundary/user-visible behavior and unit tests for pure logic.
- Run applicable build, lint, typecheck and regression checks from docs/TESTING.md.
- Record exact commands, exit codes, test names, commit and evidence per criterion. Manual checks, if needed, must include reproducible steps and observed results.
- Independent verifier writes docs/verification/M00-T04.md and proposes status change. Human review and required CI checks must pass before merge.

## Definition of done
All mandatory criteria pass; no unresolved critical/high findings; no skipped mandatory tests; documentation and registry updated. Status is authoritative in docs/tasks.json.

## Known limitations
- Alembic database migration CI execution (`uv run alembic upgrade head`) remains deferred to `M02-T01` per [ADR 0002](../decisions/0002-preview-migration-strategy.md), when async SQLAlchemy and Alembic migrations replace the provisional preview SQLite/PostgreSQL schema helper.
- GitHub branch protection rules enforcing required status checks (`backend`, `frontend`, `docker-compose`, `planning`) before merge must be configured in repository settings per `docs/TESTING.md`.
- Task-registry and verification-report schema hardening (`scripts/progress.py`) is deferred to `M00-T05`.
