# M00-T02 — Configure reproducible dependency locks

Priority: MVP | Requirement: REQ-00-02

## Dependencies
M00-T01

## Objective and scope
Implement only configure reproducible dependency locks in the repository infrastructure. Reuse existing contracts; inspect affected modules before adding new abstractions.

## Out of scope
Other task capabilities, unrelated refactoring, speculative dependencies, changing accepted contracts without an ADR.

## Acceptance criteria
- AC-01: Clean checkout installs from committed lockfiles and both builds succeed.
- AC-02: Invalid input and relevant failure paths are handled without silent success or unauthorized side effects.
- AC-03: Existing applicable regression tests pass and architecture/security constraints remain intact.

## Required verification
- Add automated tests that directly exercise AC-01 and AC-02; use integration or Playwright tests for cross-boundary/user-visible behavior and unit tests for pure logic.
- Run applicable build, lint, typecheck and regression checks from docs/TESTING.md.
- Record exact commands, exit codes, test names, commit and evidence per criterion. Manual checks, if needed, must include reproducible steps and observed results.
- Independent verifier writes docs/verification/M00-T02.md and proposes status change. Human review and required CI checks must pass before merge.

## Definition of done
All mandatory criteria pass; no unresolved critical/high findings; no skipped mandatory tests; documentation and registry updated. Status is authoritative in docs/tasks.json.

## Known limitations
- Milestone-specific libraries (such as Zustand, Zod, async SQLAlchemy/Alembic, LiteLLM, LangGraph, and MCP) remain deferred to the tasks that introduce them per ADR 0001 and `M00-T02` non-speculative scope; each future dependency change must update `backend/uv.lock` or `frontend/package-lock.json` atomically so `scripts/verify_locks.py`, `uv sync --locked`, and `npm ci` stay green.
- Docker Compose PostgreSQL service orchestration and container healthchecks are deferred to `M00-T03`; deliberate-failure CI quality gate verification is deferred to `M00-T04`.
