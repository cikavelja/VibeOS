# M00-T05 — Add task tracking and verification tooling

Priority: MVP | Requirement: REQ-00-05

## Dependencies
M00-T04

## Objective and scope
Implement only add task tracking and verification tooling in the repository infrastructure. Reuse existing contracts; inspect affected modules before adding new abstractions.

## Out of scope
Other task capabilities, unrelated refactoring, speculative dependencies, changing accepted contracts without an ADR.

## Acceptance criteria
- AC-01: Task registry validation rejects unknown dependencies and unsupported completion claims.
- AC-02: Invalid input and relevant failure paths are handled without silent success or unauthorized side effects.
- AC-03: Existing applicable regression tests pass and architecture/security constraints remain intact.

## Required verification
- Add automated tests that directly exercise AC-01 and AC-02; use integration or Playwright tests for cross-boundary/user-visible behavior and unit tests for pure logic.
- Run applicable build, lint, typecheck and regression checks from docs/TESTING.md.
- Record exact commands, exit codes, test names, commit and evidence per criterion. Manual checks, if needed, must include reproducible steps and observed results.
- Independent verifier writes docs/verification/M00-T05.md and proposes status change. Human review and required CI checks must pass before merge.

## Definition of done
All mandatory criteria pass; no unresolved critical/high findings; no skipped mandatory tests; documentation and registry updated. Status is authoritative in docs/tasks.json.

## Known limitations
- `scripts/progress.py` validates closed task schema, dependency-gated statuses, and structured verification report fields (including lowercase hexadecimal commit hash format, mandatory `PASS` criteria with substantive evidence, and non-placeholder required sections) offline from the filesystem without querying `.git` object history or remote GitHub Actions APIs; live CI run verification and human merge approval remain enforced by independent review and GitHub branch protection per `docs/TESTING.md`.
- Foundational infrastructure milestone `M00` completes upon verification of `M00-T05`; product milestones (`M01` desktop shell, `M02` async SQLAlchemy/Alembic persistence and auth, and `M03`–`M10`) remain tracked per [ADR 0002](../decisions/0002-preview-migration-strategy.md).
