# M00-T03 — Establish Docker development environment

Priority: MVP | Requirement: REQ-00-03

## Dependencies
M00-T02

## Objective and scope
Implement only establish docker development environment in the repository infrastructure. Reuse existing contracts; inspect affected modules before adding new abstractions.

## Out of scope
Other task capabilities, unrelated refactoring, speculative dependencies, changing accepted contracts without an ADR.

## Acceptance criteria
- AC-01: Compose starts frontend, API and PostgreSQL; health checks pass.
- AC-02: Invalid input and relevant failure paths are handled without silent success or unauthorized side effects.
- AC-03: Existing applicable regression tests pass and architecture/security constraints remain intact.

## Required verification
- Add automated tests that directly exercise AC-01 and AC-02; use integration or Playwright tests for cross-boundary/user-visible behavior and unit tests for pure logic.
- Run applicable build, lint, typecheck and regression checks from docs/TESTING.md.
- Record exact commands, exit codes, test names, commit and evidence per criterion. Manual checks, if needed, must include reproducible steps and observed results.
- Independent verifier writes docs/verification/M00-T03.md and proposes status change. Human review and required CI checks must pass before merge.

## Definition of done
All mandatory criteria pass; no unresolved critical/high findings; no skipped mandatory tests; documentation and registry updated. Status is authoritative in docs/tasks.json.

## Known limitations
- Provisional synchronous SQLAlchemy persistence (`make_database` with `Base.metadata.create_all`, `pool_pre_ping=True`, and `psycopg` v3 for PostgreSQL) remains active per ADR 0002 until `M02-T01` introduces async SQLAlchemy engines/sessions and Alembic migrations (`alembic upgrade head`).
- `frontend/Dockerfile` runs the Vite development server (`npm run dev`) as non-root `USER node` for local development and Compose integration testing; production static asset serving, TLS termination, and deployment hardening remain tracked under `M10-T04`.
- Deliberate-failure CI quality gate verification is tracked under `M00-T04`, and task-registry validation hardening is tracked under `M00-T05`.
