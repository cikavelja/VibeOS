# M00-T01 — Scaffold React and FastAPI

Priority: MVP | Requirement: REQ-00-01

## Dependencies
None

## Objective and scope
Implement only scaffold react and fastapi in the repository infrastructure. Reuse existing contracts; inspect affected modules before adding new abstractions.

## Out of scope
Other task capabilities, unrelated refactoring, speculative dependencies, changing accepted contracts without an ADR.

## Acceptance criteria
- AC-01: Frontend renders a health screen and API health endpoint returns success.
- AC-02: Invalid input and relevant failure paths are handled without silent success or unauthorized side effects.
- AC-03: Existing applicable regression tests pass and architecture/security constraints remain intact.

## Required verification
- Add automated tests that directly exercise AC-01 and AC-02; use integration or Playwright tests for cross-boundary/user-visible behavior and unit tests for pure logic.
- Run applicable build, lint, typecheck and regression checks from docs/TESTING.md.
- Record exact commands, exit codes, test names, commit and evidence per criterion. Manual checks, if needed, must include reproducible steps and observed results.
- Independent verifier writes docs/verification/M00-T01.md and proposes status change. Human review and required CI checks must pass before merge.

## Definition of done
All mandatory criteria pass; no unresolved critical/high findings; no skipped mandatory tests; documentation and registry updated. Status is authoritative in docs/tasks.json.

## Known limitations
- Provisional synchronous SQLite persistence (`make_database`) remains active per ADR 0002 until `M02-T01` introduces async SQLAlchemy and Alembic migrations; `/api/v1/health` runs its database readiness probe in a worker thread (`anyio.to_thread.run_sync`) to avoid blocking the async event loop.
- Reproducible lockfiles (`uv.lock`, `package-lock.json`) and ESLint script configuration are deferred to `M00-T02`.
